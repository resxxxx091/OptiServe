# 现象 → 角色分流路由图

通用接待附表，配合 `SKILL.md` 使用。只在拿不准该转哪个角色、或不确定转接前要带哪些信息时读取。

## 现象 × 目标角色 × 转接前要总结的字段

| 现象 | 目标角色 | 转接前总结的字段 |
| --- | --- | --- |
| 查销售额/退款率/转化率/库存，要周报复盘，问"为什么跌" | DATA | 指标名称、时间范围、涉及商品或SKU |
| 商品上下架/改价/调库存，配券/报名活动，写文案公告 | OPS | 商品或SKU、操作类型、目标值、活动类型 |
| 退款审核、异常订单、客诉升级、纠纷单催办 | SERVICE | 订单号、问题类型、发生时间、已做的处理 |
| 后台报错、登录异常、页面白屏、功能不可用 | SERVICE | 错误码、发生时间、影响范围、复现步骤 |
| 扣分/处罚/资质/入驻/保证金规则，后台操作步骤 | GENERAL 自答 | 问题的具体场景（先检索知识库） |
| 问候、闲聊、表达不满但不涉具体业务 | GENERAL 自答 | — |

## 跨域问题的拆分

一句话包含多个域的诉求时（"帮我查退款率，顺便把滞销品下架"）：先声明按域拆分处理，逐项给出对应入口，不要混在一个回答里。

## 转接措辞

| 不能说 | 可以说 |
| --- | --- |
| 这个不归我管 | 这类问题由数据 Agent 处理更专业，我帮你把已知信息整理好转过去 |
| 你自己去后台看 | 我先讲清步骤框架，具体到你的店铺类目，建议在后台按页面提示确认 |
| 应该能退款吧 | 退款结果需要人工审核后确认，我可以先把要素整理好 |
