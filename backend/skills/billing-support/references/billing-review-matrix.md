# 账单场景核验对照表

账单服务附表，配合 `SKILL.md` 使用。只在需要确认某个场景要核验哪些字段、是否必然转人工时读取，不必逐条复述给用户。

**本表不给任何时效数值。** 规范正文没有规定审核时长、到账天数或退款比例，写进表里的数字都是编造。对用户一律用"通常""预计""以支付渠道实际处理为准"；确实需要具体时限的场景转人工核实。

## 场景 × 核验字段 × 处理路径

| 场景 | 必须先核验的信息 | 现在就能说明的 | 处理路径 | 是否必然人工/财务 |
| --- | --- | --- | --- | --- |
| 退款申请 | 订单号、支付时间与渠道、实付金额、是否使用优惠券或余额 | 退款要走"提交申请 → 核验订单 → 审核结果 → 原路退回"，金额以实际支付金额和平台规则为准，不是订单原价 | 自助入口提交后等待审核 | 涉及已使用服务、虚拟商品、活动价、企业合同、部分退款时必然 |
| 退款显示成功但未到账 | 退款流水号、原支付渠道、提交时间 | 通过后通常原路退回，不同渠道处理时间不同；先查原支付账户入账记录和渠道通知 | 超出常规时间转人工核实流水号 | 是（要查流水） |
| 重复扣款 | 两笔扣款的时间、金额、渠道、订单号或交易截图摘要 | 会协助核实；两笔金额和时间差别较大时可能对应不同订单 | 提交财务核验 | 是，不承诺自动退回 |
| 开具发票 | 发票类型（普票/专票、电子/纸质）、抬头、税号、邮箱、订单范围与金额 | 开票前必须确认上述字段齐全 | 自助开具 | 字段缺失时先补字段 |
| 发票作废 / 重开 / 改抬头 | 原发票信息、订单范围、是否跨月、是否已报销 | 需要审核，跨月和已报销场景更慢 | 提交人工审核 | 是，且不能承诺无条件修改 |
| 取消自动续费 | 平台内订阅设置、第三方支付渠道的自动扣款协议 | 取消通常只影响后续续费，已支付的当前周期是否退款要按订单状态和退款规则审核 | 指引两处入口 | 要求退已扣费用时转退款场景 |
| 支付后要求补用优惠券 | 订单号、活动规则、券的有效期与适用范围 | 能否补用要按活动规则判断 | 提交人工审核 | 是，不承诺补差价 |
| 退款后优惠券是否退回 | 券类型与对应活动规则 | 分券种，不能一概而论 | 说明后视情况转人工 | 视规则 |

## 字段索取边界

- 可以索取：订单号或交易号、支付时间与渠道、扣款金额与币种、发票类型/抬头/税号/邮箱、脱敏后的交易截图摘要。
- 禁止索取：支付密码、短信验证码、完整银行卡号、身份证照片。
- 用户主动贴出凭证时，提醒不要在公开渠道留全量信息，复述时只写关键几位。

## 措辞替换

| 不能说 | 可以说 |
| --- | --- |
| 退款一定会通过 | 是否通过需要核验订单状态和实际支付金额 |
| X 天内到账 | 通过后通常原路退回，具体以支付渠道实际处理为准 |
| 已为您退款 / 已开票 / 这笔扣款正常 | 我在没有系统查询结果的情况下不能确认处理结果，先帮你登记核实 |
| 可以无条件重开发票 | 作废和重开需要审核，跨月或已报销更慢 |
| 一定给你补差价 | 能否补用优惠券要按活动规则判断，我提交人工核实 |
| 这是系统规定，没法处理 | 这项限制的具体规则是…如果你的情况属于…我可以转人工继续看 |
