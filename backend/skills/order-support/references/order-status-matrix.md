# 订单与物流场景对照表

订单支持附表，配合 `SKILL.md` 使用。只在需要确认某个场景能说到哪一步时读取。

**本表不做到货时效承诺。** 正文没有规定任何配送天数或送达时间点，写进表里的时间都是编造。用户问到"什么时候到"，只能说明当前订单状态和自查入口，具体时效取决于承运方与实际线路。

## 场景 × 可判断范围 × 处理路径

| 场景 | 现在能判断的事实范围 | 需要补充的信息 | 下一步 | 是否需人工 |
| --- | --- | --- | --- | --- |
| 未发货、催发货 | 只能依据用户提供的订单信息或知识库已记录的内容，不能据此断言仓库状态 | 订单号 | 说明发货状态自查入口 | 要求催促加急时需要 |
| 已发货、配送中 | 能说明"已在承运方环节"，不能推到具体送达时间 | 订单号、运单号 | 指引轨迹自查入口 | 否 |
| 物流长时间无更新 | 不能据此判定丢件，也不能判定责任方 | 运单号、最后一条轨迹的时间与地点 | 转人工向承运方核实 | 是 |
| 疑似丢件 / 异常签收 | 不能判定是否丢件、谁签收的 | 订单号、签收时间、实际收货情况 | 转人工核实 | 是，涉及赔付必然人工 |
| 修改收货地址 | 属于实际写操作，不能声称已经改好 | 订单号、新地址 | 登记后走人工，未发货与已发货的差异由人工判定 | 是 |
| 取消订单 | 属于实际写操作，不能声称已经取消 | 订单号、取消原因 | 登记后走人工；已支付订单必然要审核 | 是 |
| 支付成功但订单未生效 | 不能断定订单状态，也不能断定扣款归属 | 订单号、支付时间与渠道、支付凭证摘要 | 资金侧归账单支持，订单侧转人工 | 是 |
| 重复下单 | 不能自行判定哪一笔该留 | 两个订单号 | 需要取消已支付订单时走人工 | 是 |
| 订单金额异常 | 不能直接认定系统错误 | 订单号、下单时间、页面显示的金额与实付金额 | 转账单支持按账单场景核实 | 是 |

## 字段索取顺序

- 一次只问一个字段：订单号优先，其次下单时间，再次收货手机号后四位。
- 用户没给订单号时，不要同时追问时间、地址和运单号；先要订单号，拿到再继续。

## 措辞替换

| 不能说 | 可以说 |
| --- | --- |
| 我查了后台，你的订单已经发货 | 我这边没有后台查询能力；按你提供的信息，这笔订单目前的状态是… |
| 预计三天到 / 明天肯定能收到 | 具体到货时间取决于承运方和线路，我给不了确切时间 |
| 已经帮你改好地址了 | 地址变更需要人工处理后生效，我先登记你的诉求 |
| 这个单子肯定能取消 | 已支付订单的取消需要人工审核，我提交上去 |
| 显示签收了就是你收到了 | 签收记录与实际收货不一致时，需要人工向承运方核实 |
